Движок AJAX-фильтрации каталога, который читает HTML-атрибуты pf-* прямо в разметке темы: WooCommerce-товары, любой тип записи, произвольное число независимых профилей и блоков фильтра на одной странице.

== Description ==

PF Filter работает через контракт HTML-атрибутов `pf-*` в разметке темы: тема отвечает за HTML, CSS и внешний вид карточек, сетки и фильтров, плагин находит нужные элементы по этим атрибутам, строит фасетный фильтр, обменивается данными с собственным REST API и обновляет список записей, счётчики, пагинацию и активные фильтры без перезагрузки страницы.

= Принцип работы =

Разметка описывает намерение через атрибуты, а плагин интерпретирует её и наполняет данными — структура, стили и оформление каждого элемента остаются решением верстальщика. Отсутствие необязательного атрибута выводит предупреждение в консоль браузера и мягко деградирует; отсутствие обязательного — ошибку в консоли, при этом инициализация остальной страницы продолжается там, где это возможно. Из собственного CSS плагин добавляет только служебные утилитные классы для скрытия элементов — визуальная стилизация целиком принадлежит теме.

Первая загрузка страницы рендерится обычным циклом WordPress — плагин включается только на AJAX-обновлениях. Для них он сам находит настоящий PHP-файл, которым тема рисует карточку записи (архив, встроенный блок фильтра на произвольной странице, главная), и извлекает из него код цикла — карточки при фильтрации выглядят один в один с исходной страницей, без создания отдельных шаблонов под плагин.

= Возможности =

**Любой тип записи и таксономия.** С активным WooCommerce товары фильтруются со всеми своими особенностями — атрибуты, наличие, цена, скидка. Для любого другого типа записи сайта (блог, кастомный CPT) плагин строит фильтр по его таксономиям и числовым ACF-полям.

**Профили фильтра.** Настройки организованы как список независимых профилей — у каждого свой тип записи, группы фильтров, пагинация, сортировка. Атрибут `pf-profile="id"` в разметке одновременно выбирает профиль и задаёт границу блока фильтрации, поэтому на одной странице уживаются несколько независимых блоков — например, фильтр услуг рядом с фильтром новостей на главной.

**Шаблоны групп фильтра:** чекбоксы, радио, теги, дерево категорий для любой иерархической таксономии с настраиваемой глубиной вложенности (ограничение действует и на плоских шаблонах), диапазон/слайдер для цены и любого числового ACF-поля записи с произвольным числом независимых range-групп сразу, наличие товара для WooCommerce. Для любого шаблона можно свёрстать несколько вариантов оформления (например, чекбоксы плоским списком и те же чекбоксы внутри дропдауна темы) и выбрать нужный вариант для конкретной группы в настройках.

**Диапазон/слайдер:** перетаскивание бегунков, прямой ввод значения числом в поле (с подсказкой текущей границы), полоска подсветки между бегунками — управляется через pf-* атрибуты.

**Режим применения фильтра.** По умолчанию каждое изменение сразу обновляет список. Можно переключить на «По кнопке» — список, пагинация, чипы и URL ждут клика по `pf-apply`, а счётчики значений и границы диапазона продолжают обновляться вживую под ещё не применённый выбор.

**Сортировка:** по умолчанию, по дате в обе стороны, для WooCommerce — по цене, популярности, рейтингу, размеру скидки, плюс по любому ACF-полю записи и по названию значения атрибута/таксономии.

**Диагностика.** Отдельная вкладка в настройках проверяет окружение сервера, разметку конкретной страницы каталога и собственные REST-эндпоинты — актуальный результат при каждом запуске.

Полное описание атрибутов, REST API и структуры конфигурации — см. REFERENCE.md в репозитории проекта.

== Installation ==

1. Загрузите папку `pf-filter` в `/wp-content/plugins/`.
2. Активируйте плагин через меню «Плагины» в WordPress.
3. На странице Настройки → PF Filter создайте профиль (или используйте профиль по умолчанию), выберите тип записи и настройте группы фильтров и сортировку.
4. Разметьте страницу каталога атрибутами `pf-form`, `pf-target` (если форм/списков на странице несколько), `pf-list`, `pf-output`, `pf-templates`, `pf-profile` (если профилей на сайте несколько или блоков фильтрации на странице несколько) и т.д.

== Changelog ==

= 2.4.1 =
* Если в карточках товара есть слайдер, галерея или анимация (Swiper, Slick, AOS и другие популярные библиотеки) — теперь это можно донастроить так, чтобы оно продолжало работать и после фильтрации: тема получает сигнал об обновлении списка, а диагностика в админке сама подсказывает, если заметит такую библиотеку в карточках, и что с этим сделать.

= 2.3.0 =
* Ценовой диапазон можно оформить только текстовыми полями «от — до», без визуального ползунка — тема сама решает, нужен ли ей слайдер.
* Настройка и диагностика плагина в админке теперь корректно работают уже на этапе запуска магазина, до его открытия для покупателей.
* Исправлено отображение карточек товара при обновлении списка фильтром — для карточек, которые показывают переключатель вариаций товара (например, выбор объёма памяти или цвета), список товаров теперь всегда выглядит так же, как при обычной загрузке страницы.
* Плагин точнее сообщает о причине проблемы в журнале отладки сайта — это ускоряет диагностику на реальных сайтах.

= 2.2.0 =
* Режим применения фильтра (`filter_mode`, настройка профиля) — «Сразу» (как раньше, по умолчанию) или «По кнопке»: список, пагинация, чипы активных фильтров и URL обновляются только по клику на новый атрибут `pf-apply`, при этом счётчики значений и границы диапазона продолжают обновляться вживую под ещё не применённый выбор. Сортировка, пагинация и сброс фильтров всегда срабатывают сразу в обоих режимах.
* Диагностика предупреждает, если режим «По кнопке» включён, а `pf-apply` не найден в разметке страницы.

= 2.1.0 =
* Вариант оформления шаблона группы (`pf-template-variant`) — для любого шаблона (не только чекбоксов/радио) можно свёрстать несколько разных по разметке блоков и выбрать нужный вариант для конкретной группы фильтра в настройках; список вариантов строится сканированием разметки, подпись — сам слаг варианта.
* `dropdown-checkbox`/`dropdown-radio` убраны как отдельные типы шаблона — были чистой визуальной обёрткой без собственной логики поверх `checkbox`/`radio`, теперь это просто один из вариантов оформления (см. выше). Обратная совместимость с сохранёнными настройками не сохранялась намеренно.

= 2.0.0 =
Первый публичный релиз.

* Фасетный AJAX-фильтр каталога, управляемый HTML-атрибутами pf-* в разметке темы — WooCommerce-товары, любой другой тип записи, произвольное число независимых профилей и блоков фильтра на одной странице.
* Шаблоны групп: чекбоксы, радио, теги, дропдаун, дерево категорий с настраиваемой глубиной, диапазон/слайдер, наличие товара.
* Диапазон/слайдер с перетаскиванием бегунков, прямым вводом значения числом и полоской подсветки между бегунками.
* Гибкая сортировка: по умолчанию, по дате в обе стороны, для WooCommerce — по цене/популярности/рейтингу/скидке, по любому ACF-полю записи и по значению атрибута/таксономии.
* Автоматическое извлечение шаблона карточки записи из реального PHP-файла темы — карточки при AJAX-обновлении выглядят один в один с обычной загрузкой страницы.
* Диагностика окружения сервера, разметки страницы и собственных REST-эндпоинтов прямо в настройках.
* Facet-счётчики групп фильтра считаются без лишних повторяющихся запросов; персистентный кэш кастомных атрибутов товаров с автоматическим обновлением по хукам и расписанию и ручной кнопкой обновления.
* Пройден аудит безопасности: параметризованные SQL-запросы, экранированный вывод, проверка прав и nonce на всех действиях, изменяющих состояние.
